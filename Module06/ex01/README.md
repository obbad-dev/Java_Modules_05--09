# Exercise 01: Embedded DataBase

## Exercise Overview
The objective of **Exercise 01** is to create an in-memory database configuration using **HSQLDB** and Spring JDBC's `EmbeddedDatabaseBuilder` for integration testing.

Instead of requiring an external database server (like PostgreSQL), tests spin up a lightweight, isolated SQL database directly inside the JVM process. We prepare `schema.sql` and `data.sql`, configure the DataSource in `@BeforeEach`, and verify the connection.

---

## Concepts

1. **In-Memory Embedded Databases (HSQLDB)**
   - Embedded databases live in RAM during JVM execution.
   - They allow testing SQL queries and schema constraints without installing or maintaining external database services.
2. **Spring JDBC `EmbeddedDatabaseBuilder`**
   - A builder utility provided by `spring-jdbc` that creates an `EmbeddedDatabase` (which implements `javax.sql.DataSource`).
   - Automatically executes DDL (`schema.sql`) and DML (`data.sql`) upon creation.
3. **Test Lifecycle & Isolation (`@BeforeEach`)**
   - Running tests sequentially against a shared database can cause cross-test contamination (e.g. one test deletes a row needed by another).
   - Rebuilding the embedded database before *every* test ensures each test executes against a known, pristine state.

## My Implementation

### Database Scripts (`src/test/resources/`)
- `schema.sql`:
  ```sql
  CREATE TABLE product (
      id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      name VARCHAR(100) NOT NULL,
      price DECIMAL(10, 2) NOT NULL
  );
  ```
- `data.sql`:
  Inserts 5 sample products (e.g. `Wireless Mouse`, `Mechanical Keyboard`, `USB-C Hub`, `Gaming Monitor`, `Noise Cancelling Headphones`).

### Test Implementation (`EmbeddedDataSourceTest.java`)
- `init()` annotated with `@BeforeEach`:
  ```java
  dataSource = new EmbeddedDatabaseBuilder()
      .setType(EmbeddedDatabaseType.HSQL)
      .addScripts("schema.sql", "data.sql")
      .build();
  ```
- `testMethod()`:
  - Opens a connection via `dataSource.getConnection()`.
  - Asserts `assertNotNull(con)`.
- `testSimpleQuery()`:
  - Executes `SELECT COUNT(*) FROM product`.
  - Asserts that the table contains 5 records (`assertEquals(5, rs.getInt(1))`).

---

## How It Works

1. When JUnit starts each test method, `@BeforeEach init()` is invoked first.
2. `EmbeddedDatabaseBuilder` initializes an in-memory HSQL instance.
3. It loads `schema.sql` from the test classpath and executes table creation.
4. It loads `data.sql` and populates the 5 rows.
5. The test runs, interacting with the fresh database.
6. When the test completes, the next test starts by re-executing `init()`, restoring the original state.

## Important Things to Understand (for Evaluation / Code Review)

1. **What are the advantages of HSQLDB over PostgreSQL for integration tests?**
   - Zero external configuration required.
   - Extremely fast startup and execution.
   - Complete isolation between test runs.
2. **Why does `EmbeddedDatabaseBuilder` take classpath script names?**
   - Maven places files from `src/test/resources/` onto the test classpath, making them accessible to Spring's resource loaders without absolute file system paths.
